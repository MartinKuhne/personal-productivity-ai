# Introduction

![Status: Planned](https://img.shields.io/badge/status-Planned-2196F3)

This plan migrates the FastMD user interface from **egui/eframe 0.36** (immediate-mode) to **iced 0.14.0** (The Elm Architecture / reactive rendering). The domain layers — `src/app/{markdown,bus,config,workspace,background,agent,export}`, `src/agent`, `src/md2pdf`, `src/fastmd-tool-macros` — are unaffected. Only the UI layer (`src/app/ui/`, 75 non-test source files, 20,380 lines) and the window bootstrap (`src/app/main.rs`) change. The migration is incremental: a parallel iced content module and a parallel binary target keep the egui UI fully working until Phase 5 swaps it out and deletes egui.

Reference material: [our iced SDK documentation](doc/iced.md), the [iced book](https://github.com/iced-rs/book/tree/master/src), and [docs.rs/iced 0.14](https://docs.rs/iced/0.14.0/iced/).

## 1. Requirements & Constraints

- **REQ-001**: Full functional parity with `src/app/ui/SPEC.md` (`UI-001`..`UI-066`). Every `UI-xxx` requirement listed there MUST remain traceable to a behavior in the iced UI. The traceability matrix is produced in TASK-002.
- **REQ-002**: 5-pane layout preserved (`UI-001` Pane Structure): top, bottom, left, right, center panes with the same behaviors (resizable panes, tabbed center area).
- **REQ-003**: Markdown viewing stays the core feature (`REQ-301` root summary; markdown subsystem is out of scope and MUST NOT be modified).
- **REQ-004**: Editor parity (`UI-037`..`UI-045`): inline editor with content editing, selection, clipboard, cursor navigation, undo/redo, validation, save/cancel. `UI-046` (inverted black-on-white editor color scheme) is DROPPED from scope by DEC-002 (2026-10-17).
- **REQ-005**: Context menus preserved (`UI-006`..`UI-015`, `UI-023`..`UI-026`, `UI-034`): directory-tree, tab, and multi-select context menus with all current menu items.
- **REQ-006**: Search preserved: content search (`UI-050`) and tree search.
- **REQ-007**: Background process log tab preserved (`UI-047`; `REQ-460..465` in `src/app/background/SPEC.md`). Log buffer stays owned by `src/background/`.
- **REQ-008**: Agent UI parity (`UI-048`, agent panel, batch dialog, tools dialog, agent debug window).
- **REQ-009**: Workspace/indexer responsiveness architecture preserved (`FMD-060`..`FMD-072` in `src/app/AGENTS.md`): UI stays responsive during background work, commands are deterministic and replayable, state is only mutated on the UI thread, cross-subsystem interactions remain observable events.
- **REQ-010**: Comprehensive test coverage (2026-10-17 directive): the deliverable UI MUST be covered at FOUR tiers — (1) unit tests (existing nextest suite + new sidecar tests), (2) headless interaction tests via `iced_test::simulator` (`click`/`typewrite`/`find`/`into_messages`), (3) visual baselines via `Simulator::snapshot` / `iced_test::screenshot`, and (4) recorded `.ice` end-to-end flows via `iced_tester` → `iced_test::run` with `program::Preset`. Every `UI-xxx` requirement in the TASK-002 traceability matrix MUST cite at least one tier artifact.
- **SEC-001**: No new `unsafe` code. The iced workspace already denies `unsafe_code`; the fastmd workspace MUST NOT enable any iced feature that requires unsafe, and our code MUST NOT add `unsafe` blocks.
- **SEC-002**: No new secrets, configuration storage paths, or file writes. Persistence rules (`RUST-024`: injectable storage handlers) apply unchanged.
- **CON-001**: Target release: `iced = "0.14.0"` from crates.io. DECIDED 2026-10-17 (DEC-001): 0.14.0 is the release; master `0.15.0-dev` MUST NOT be introduced except under explicit new user instruction (see ALT-003, which records the rejected option).
- **CON-002**: Single framework per window. eframe/egui and iced MUST be in the same crate only during the incremental phases; each binary target depends on exactly one UI framework.
- **CON-003**: Legacy test harness (`egui_kittest`, 416 matching references across `src/app/ui/**`) is not compatible with iced. The kittest snapshot suite MUST be replaced in Phase 5, not translated one-for-one (see TEST-004..TEST-006).
- **CON-004**: Startup order dependency: building a iced app requires `FastMdApp`'s state to be constructible without an egui context (the current `ui::app::init` contrast: `new(cc: &eframe::CreationContext<'_>, ...)` takes the eframe creation context). State extraction from egui types is part of Phase 1.
- **CON-005**: Quality gate MUST pass after every task: `cargo check`, `cargo clippy -- -D warnings`, `cargo nextest run --status-level fail --show-progress none`, `cargo fmt --check`, `cargo doc --no-deps --quiet`.
- **CON-006**: Rule [RUST-058] (`app/` is egui-free) becomes fully enforceable at completion: after Phase 5, no `.rs` file under `src/app/` imports egui or eframe.
- **GUD-001**: [RUST-010]/[RUST-011]: every new module has a `//!` doc comment asserting its purpose; every `pub` item has a `///` doc comment. Also [RUST-057]: sidecar test files end with the one-line pointer note in the source module doc.
- **GUD-002**: User-facing strings MUST stay in `src/app/ui/strings.rs` as `pub const` and be referenced via `crate::ui::strings::<CONST_NAME>` (rule in `src/app/AGENTS.md`). iced code reuses the same constants.
- **GUD-003**: Numeric colours MUST stay in `src/app/ui/theme.rs` as `Palette`/`EditorColors` tokens; iced code resolves colours via the same tokens mapped into iced theme structures.
- **PAT-001**: The Elm Architecture pattern (Model / Messages / update / view) with a single top-level `Message` enum and sub-modules using scoped message variants, mirroring `iced` conventions (one state, one message enum per app).
- **PAT-002**: Events flow background → UI only (`FMD-065`). The iced integration MUST consume the existing `Bus<ConfigArrived>`-style broadcasts and wake the runtime via `iced::Task` / `iced::Subscription` conversion; it MUST NOT synchronously invoke the bus.

### Decision log (2026-10-17)

- **DEC-001**: Version locked: `iced 0.14.0` from crates.io. Supersedes the ALT-003 0.15-dev fallback trigger; a version change now needs an explicit new user decision.
- **DEC-002**: `UI-046` (inverted black-on-white editor scheme) is dropped from roadmap scope. It remains defined in `src/app/ui/SPEC.md` [SPEC untouched, per RUST-043].
- **DEC-003**: Accessibility (`eframe` `accesskit` feature, and the `accesskit::Role` assertions in `ui/widgets_tests.rs:183`) is dropped from migration scope. No a11y requirements are added to this plan; role-asserting kittest tests are removed with the old harness.
- **DEC-004**: `UI-016` (adaptive tree width, max 20% viewport), `UI-017` (directories before files), `UI-018` (hide empty folders) REMAIN requirements and are re-solved on iced (`TASK-012`); current constants `LEFT_PANEL_MAX_WIDTH_FRACTION` (0.2), `LEFT_PANEL_DEFAULT_WIDTH`, `LEFT_PANEL_MIN_WIDTH` in `ui/panel_layout.rs:1-23` carry over.
- **DEC-005**: Context menus and dialogs are implemented with iced **built-ins only** (verified in 0.14): `iced::widget::overlay::menu` (dropdown menus with `State`/`Style`) with `iced::widget::MouseArea` press wiring for right-click behavior, plus `overlay`/`Stack` for modals. Third-party `iced_aw` `ContextMenu` is NOT adopted (0.14 compatibility UNVERIFIED; known overlay bugs iced_aw#378 hover-state, iced_aw#363 style-blank). Revisit only if the built-in construction proves expensive in `TASK-017`.
- **DEC-006**: UI state persistence keeps the existing pure serde model `src/app/ui/persisted.rs` (`PersistedUiState`: schema-versioned, fields left/right widths, window x/y/w/h, font size scale, expanded dirs, about-shown stamp) and swaps the `eframe::Storage` backend for: save via subscription to `iced::window::close_requests()`/`close_events()` (verified in `iced::window` docs) + restore at boot via `iced::window::Settings`; storage file location through the `RUST-024` injectable storage handler.
- **DEC-007** (2026-10-17, user directive): the inline editor is built on **`iced::widget::text_editor`**. Verified against `iced_core-0.14.0/src/text/editor.rs`: `Action::{Move(Motion), Select(Motion), SelectWord, SelectLine, SelectAll, Edit(Edit)}` with `Edit::{Insert, Paste, Enter, Indent, Unindent, Backspace, Delete}` covers selection/caret/paste natively, but there is **NO undo/redo history** in the widget (no `Undo`/`Redo` anywhere in `Action`/`Edit`). `UI-042` is therefore implemented at OUR layer: every `Action::Edit` is intercepted (the widget publishes applied `Action`s via its `on_edit` callback, verified `iced_widget-0.14.2/src/text_editor.rs:796,844,865-874`), snapshots content+caret into per-tab history stacks in state BEFORE applying, and `Message::Undo`/`Message::Redo` replay snapshots. Keeps `FMD-068` (replayable commands) by construction.
- **DEC-008** (2026-10-17): font scaling model. Text sizes are logical pixels (book/documented). The runtime default scale factor is the winit/OS DPI factor; the `iced::application` builder's `.scale_factor(impl Fn(&State) -> f32)` (verified `iced-0.14.0/src/application.rs:410-426`) REPLACES that default with a state-aware value. Therefore the FastMD approach: `boot` returns a `Task` that reads the OS baseline once via `iced::window::latest() -> Task<Option<Id>>` + `iced::window::scale_factor(id) -> Task<f32>` (both verified in `iced_runtime-0.14.0/src/window.rs`), stores it as the OS baseline (replacing the egui `pixels_per_point` logic), and the `scale_factor` closure composes `baseline × persisted_font_scale` — preserving `PersistedUiState::font_size_scale` multiplier semantics (including the v0→v1 migration) verbatim.
- **DEC-009** (2026-10-17, user directive): config arrival is adapted to iced best practice. `Program::boot(&self) -> (State, Task<Message>)` is VERIFIED (`iced-0.14.0/src/application.rs:124`), so the `boot` closure may return an initial `Task`. New model: (a) construct `FastMdApp` and ALL subscribers inside `boot` (subscribers exist before any publish), (b) direct-inject the already-loaded `config` into state during boot — no startup broadcast needed for the UI itself, (c) publish `ConfigArrived` on the existing bus FROM a `Task::perform` returned by `boot` so background workers still observe the arrival event with the ordering guarantee the `main.rs:147-160` comment enforces, (d) any later runtime config changes keep flowing through subscriptions converted per `FMD-066`/`FMD-067`. This replaces the egui "publish after Box::new" workaround rather than replicating it.

## 3. Alternatives

- **ALT-001**: Stay on egui/eframe 0.36 (status quo). Rejected: it preserves a known-good production UI with essentially zero risk, but the UI gains nothing from iced reactive rendering and the Rust-native Elm architecture.
- **ALT-002**: Big-bang migration (delete egui in one commit, port everything at once). Rejected: 20,380 lines of UI source cannot land atomically with a green quality gate. Incremental parallel-binary approach (Phases 1..3) keeps the shipping egui build intact and keeps feedback cycles short.
- **ALT-003**: Use iced master `0.15.0-dev` from the GitHub repository instead of crates.io 0.14.0. REJECTED BY DEC-001 (2026-10-17): version locked to 0.14.0; this option survives only as a future decision that requires explicit user instruction.
- **ALT-004**: Hybrid: keep egui only for the inline markdown editor inside an iced window. Rejected: two renderers cannot share one window (`CON-002`), and bridging them would duplicate layout and complexity around resizing.
- **ALT-005**: Migrate to a different framework (`Slint`, `GPUI`). Rejected: iced was selected by the user; iced matches FastMD's Elm-shaped subsystems (`update`/`view` methods on application state) better and is pure Rust like the rest of the workspace.

## 7. Risks & Assumptions

- **RISK-001**: `iced` master (`0.15.0-dev`) churns its API between releases; features assumed stable in this plan may shift. Mitigated by pinning to 0.14.0 (`CON-001`) and by treating `doc/planning/iced-migration-map.md` as the contract that must re-verify each entry against docs.rs before its task starts.
- **RISK-002**: Text editor feature parity — CONFIRMED & MITIGATED BY DESIGN 2026-10-17: `iced::widget::text_editor` has NO native undo/redo stack (verified in `iced_core-0.14.0/src/text/editor.rs`; RISK-002 closed as a discovery risk). Design is fixed in DEC-007 / TASK-014 (history snapshots intercepted via `on_edit`, replayed by `Message::Undo`/`Message::Redo`). Residual risk: snapshot memory growth for very large buffers; mitigate with bounded history depth, tunable later.
- **RISK-003**: RESOLVED 2026-10-17: snapshot/test harness availability confirmed — `iced_test 0.14.0` + `iced_tester 0.14.0` are published (see `DEP-003`). Remaining (small) risk: `Simulator` selectors query by rendered text, so assertion targets need stable strings or widget `Id`s — covered by existing `egui::Id` stability rules (`AGENTS.md §5`) ported to `iced::widget::Id` (`TASK-002` traceability).
- ~~**RISK-003 (old)**~~: superseded.
- **RISK-004**: Visual parity regression: fonts, sub-pixel antialiasing, table layout, and dark theme rendering will differ subtly from egui/eframe. Mitigation: all numeric colours stay behind `crate::ui::theme::Palette` (`GUD-003`); snapshots are re-authored rather than image-diffed against old baselines (TASK-026).
- **RISK-005**: 20k lines of UI logic migration is the largest refactor in the repo. Mitigation: incremental phases each leave the quality gate green; parallel binary (`fastmd_iced`) preserves the working egui build until Phase 5.
- **RISK-006**: Dual dependency tail (`eframe` + `iced` in the same build increases binary size). Temporary during Phases 1..4 only. [INFERENCE] Final binary size MUST NOT exceed the pre-migration size by more than ~10%.
- **ASSUMPTION-001**: The workspace stays desktop-only (Windows primary); Wasm builds are out of scope for this plan.
- **ASSUMPTION-002**: `src/app/ui/SPEC.md` `UI-xxx` IDs remain stable during the migration (`RUST-043`: SPEC.md files are not modified by this plan).
- **ASSUMPTION-003**: The bus/orchestrator event contracts (`FMD-066`, `FMD-067`) stay unchanged; the iced subscription bridge is a pure consumer.
- **ASSUMPTION-004**: `cargo nextest` remains the test runner (`RUST-002`); tier-4 snapshot tests use the `default` profile in `.config/nextest.toml`.
